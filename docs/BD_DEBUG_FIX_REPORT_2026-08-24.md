# BD debug: отчёт об исправлениях

Дата: 2026-08-24  
Ветка: `bd-debug`  
Базовый commit после синхронизации с `origin/dev-ios`: `ca247231`

## Основание

Исправления подготовлены по результатам аудита `client_error_reports` для версий приложения начиная с 1.4.0. База данных во время разработки решений не изменялась; повторное SSH-подключение не выполнялось.

## Реализованные решения

### Клиентская диагностика

- Служебные `event=...` записи и строки Go stack trace остаются в хвосте логов, но больше не создают самостоятельные отчёты об ошибках.
- Fingerprint нормализует UUID, адреса и порты, PID, generation, sequence number, monotonic time, timestamps и hex-адреса.
- Одинаковый fingerprint отправляется не чаще одного раза за 10 минут; кэш ограничен 256 значениями.
- Стабильный device ID перед отправкой преобразуется в SHA-256 pseudonymous ID.
- Из payload удалены login, имя/ID профиля и host URL профиля. Сохраняются только тип профиля и срок действия remote-профиля.
- Ожидаемые HTTP/404 ошибки опционального auto-selection переведены с error на warning.
- Ошибка чтения профилей теперь сохраняет исходный failure и stack trace вместо сообщения без причины.

### Профили и локальное хранилище

- Удалено повторное `Uri.decodeComponent` для уже декодированных `Uri.pathSegments` в импорте mobile link и bind-account flow.
- Drift настроен с `shareAcrossIsolates: true` для совместной работы foreground и WorkManager.
- При открытии SQLite включаются WAL и `busy_timeout=5000`, чтобы короткая конкуренция записи не становилась пользовательской ошибкой `database is locked`.
- После первого создания ключа шифрования сохраняется marker и проверяется наличие `.zcfg` файлов. Если ключ исчез, новый ключ поверх существующих зашифрованных данных больше не генерируется.

### VPN, Riverpod и UI

- Репозиторий соединения, preference notifier и native snapshot source фиксируются до первого async gap. Status loop больше не читает эти зависимости через `ref` после возможной invalidation.
- `_acceptPlatformStatus` получает snapshot и user intent явно, включая platform resync.
- Не готовый во время bootstrap диагностический контроллер не блокирует запуск VPN.
- Router fallback проверяет `context.mounted` и переходит по стабильному пути `/home`.
- Ветка синхронизирована с `ca247231 fix(apple): prevent VPN UI lifecycle stalls`, включающим защиту поколений сессии, authoritative snapshots, START/STOP reconciliation и устранение rebuild-конфликтов Home/active proxy.

## Ограничения и оставшиеся риски

- Уже повреждённый `.zcfg` невозможно расшифровать без исходного ключа. Новая защита предотвращает дальнейшую тихую потерю и выдаёт диагностируемую ошибку; восстановление требует исходного ключа либо повторного импорта профиля.
- Низкоуровневые ошибки bbolt/core и разрешений VPN зависят от платформы и должны быть подтверждены на физических Android/iOS/Windows устройствах. В этом изменении они не маскируются как исправленные.
- WAL и timeout снижают вероятность SQLite lock contention, но не заменяют device-тест длительной параллельной работы foreground и WorkManager.
- Изменения не закоммичены. Пользовательский файл `scripts/package_windows_installers.ps1` сохранён без вмешательства.
